# Knowledge Definition

## 1. Knowledgeとは

N-IE LabのKnowledgeは、特定の経験や記事から抽出した、他者が別の状況でも再利用できる知識単位である。

単なる用語説明、感想、資格問題の解答、note記事の転載ではない。読者が「何を問い、何を見て、どう判断し、どのように確かめるか」を持ち帰れる形にする。

## 2. 最低限含める内容

- このKnowledgeが答える問い。
- 定義。
- なぜ重要か。
- 基本構造または因果関係。
- 判断軸。
- 適用場面。
- 注意点、限界、よくある失敗。
- 関連するKnowledge、ケース、ツール。
- 出典。
- `updatedAt` と更新条件。

すべてを長文化する必要はないが、定義だけで終わらせない。

## 3. 実務判断フレーム

実務上の問題を扱うKnowledgeでは、必要に応じて次の流れを使う。

```text
WHY   目的・要求・基本機能を定める
  ->
WHAT  評価する品質特性・指標・状態を定める
  ->
HOW   試験・統計・改善・管理方法を選ぶ
  ->
CHECK 結果と副作用を評価する
  ->
LEARN 学びを標準、設計、教育、次の判断へ残す
```

これはN-IE Labの実務判断用フレームであり、既存理論の名称を置き換えたり、単純に転記したりするものではない。個別理論と接続する場合は、共通点と相違点を明示する。

## 4. 配置と分類

- Knowledgeは「品質をつくる」「生産を整える」「データで確かめる」「改善を仕組みにする」の既存4テーマ内へ置く。
- 既存の `content/guides/{exam}/` と公開URL体系を使う。
- `contentType` は内容の主目的に合わせる。
- 新しいトップレベルカテゴリとしてKnowledgeを追加しない。

## 5. 新規作成しない判断

次の場合は `No standalone Knowledge needed` と判断する。

- 既存ページが同じ問いと検索意図に十分答えている。
- 個人の経験に依存し、一般化できる判断軸がない。
- 定義、適用条件、出典を確認できない。
- 単独ページより、既存ページへの短い補足やリンクの方が読者価値が高い。
- 内容が小さく、関連Knowledgeの一節として扱う方が自然である。

## 6. 重複と正本

新規作成前に、既存URL、タイトル、タグ、本文検索を行う。重複する場合は正本をひとつにし、必要に応じて既存ページを補強する。同一本文をnoteとサイト、または複数の公開URLへ掲載しない。

## 7. 更新条件

規格、法令、公的資料、技術前提、適用例が変わったときに再確認する。歴史的な資料を使う場合は、その時点の記述であることを示す。
