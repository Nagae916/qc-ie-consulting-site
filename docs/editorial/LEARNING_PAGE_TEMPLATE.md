# Learning Page Template

## 目的

参考書の定義だけでは理解しにくい概念を、図と小さな例で確かめられるKnowledgeへ編集する。固定テンプレートへ本文を押し込まず、読者の疑問と題材の性質に合わせて順序や図の種類を変える。

## 基本の読解順序

1. **疑問と短い答え**：このページが解く疑問と、先に持ち帰れる答え。
2. **主図**：文章を圧縮し、何を見るかをcaptionで示す図。
3. **小さな例・操作**：状態や条件の違いを比較する最小例。静止状態でも意味が通ること。
4. **理由と定義**：図で見た現象を用語、式、因果関係へ接続する。
5. **適用条件と注意**：使える条件、使えない条件、混同しやすい判断。
6. **関連知識と出典**：読む理由を付けた最大3件と、確認日を伴う根拠。

すべての章を必須にはしない。比較が中心なら比較表、因果が中心ならflow、数値判断が中心なら計算と図を主役にする。

## 再利用する最小コンポーネント

- `LearningQuestion`: 疑問と短い答え。
- `LearningFigure`: 図、図題、caption。図そのものの実装は題材別に分ける。
- `LearningExample`: 小さな例、判断上の注意、条件の補足。

図や操作を一つの汎用コンポーネントへ抽象化しない。管理図の計算・SVGは `ControlChartLearningDemo` と純粋計算モジュールに分け、他の題材はそれぞれの正しいモデルを持つ。

## メタデータ

- `knowledgeId`: URLに依存しない安定ID。
- `primaryArea` / `subtopics`: 主領域と中項目。
- `learningOutcomes`: 読了後にできる説明・判断。
- `knowledgeRelations`: `prerequisite` / `together` / `application` と読む理由。
- `sources`: 出典、URL、確認日。
- `reviewedAt`: 内容を確認した日。ビルド日時ではない。

既存ページでは任意項目とし、更新する少数ページから段階導入する。

## 表示とアクセシビリティ

- H1はページレイアウトが一つだけ出し、本文はH2以下とする。
- 本文は16px以上、行間1.7〜1.9を目安に日本語実画面で調整する。
- 図はtitle、caption、軸、単位、凡例、データの実在性を示す。
- 操作はnative controlを優先し、キーボード、focus表示、リセット、色以外の識別を備える。
- 360〜390px、1280〜1440px、200%拡大で横あふれと読解順序を確認する。

## 完了条件

- 問い、図、小さな例、適用上の注意が矛盾しない。
- 数値と判定は同じ計算正本へ対するテストで確認する。
- 関連先の本文が、示した読む理由に実際に答える。
- URL、canonical、公開状態、既存機能を保全する。
- 仮想ペルソナの評価は実利用者の反応と区別する。
