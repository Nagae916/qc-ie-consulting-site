# Learning Content Agent Handoffs

## 共通入力

各ジョブは、対象ID、読者の疑問、到達点、入力資料、一次資料、変更可能ファイル、受入条件、状態、残課題を持つ。不足や矛盾を推測で埋めず、`資料待ち` または `要確認` として返す。

## 1. 調査・分類

- **目的**：正本URL、重複、前提Knowledge、一次資料、数値条件を確定する。
- **入力**：対象ID、既存ページ、検索意図、候補資料。
- **成果物**：重複判定、残すURL、読者の疑問、出典表、前提Knowledge、未確認事項。
- **完了条件**：新規ページの必要性と、事実・仮想例の区別を説明できる。
- **変更可能範囲**：ジョブ記録の調査欄のみ。公開本文は変更しない。

## 2. 制作

- **目的**：疑問に答える本文、図、小さな例、必要最小限の操作を作る。
- **入力**：承認済み調査結果、Learning Page Template、既存コンポーネント。
- **成果物**：MDX、題材固有の図・計算、テスト、出典・確認日。
- **完了条件**：図、データ、説明、計算が一致し、静止状態でも理解できる。
- **変更可能範囲**：ジョブで許可されたコンテンツ、コンポーネント、純粋ロジック、テストのみ。

## 3. 関連づけ

- **目的**：本文理解に必要なKnowledgeへ、読む理由を付けて接続する。
- **入力**：制作物、既存 `knowledgeId`、公開Knowledge本文。
- **成果物**：関係種別、URL、タイトル、読む理由。末尾表示は最大3件。
- **完了条件**：URLが実在し、リンク先本文が読む理由に答え、本文中リンクと重複しすぎない。
- **変更可能範囲**：対象frontmatterと必要な本文リンク。関連先本文の増量は別ジョブ。

## 4. 検証

- **目的**：数値、根拠、表示、リンク、公開制御を独立に点検する。
- **入力**：差分、テスト、Previewまたは同一SHAのProduction build、受入条件。
- **成果物**：検証結果、画面証跡、未実行事項、回帰、残課題。
- **完了条件**：typecheck、lint、build、必要監査、360〜390px・1280〜1440px・200%・キーボードを確認する。
- **変更可能範囲**：原則レビューのみ。明確な欠陥の修正はOrchestratorへ戻す。

## 状態と権限

状態は `調査中`、`制作中`、`検証中`、`資料待ち`、`要確認`、`レビュー待ち`、`完了` を使う。Agentの自律範囲は専用ブランチ上の下書き、実装、検証、Draft PRまで。mainへのmerge、Production公開、外部投稿、課金、定期実行、新規APIは行わない。
