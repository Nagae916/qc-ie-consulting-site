# 学習ガイドの初回配信JS検証（2026-11-19 JST）

## 実行条件

- モデル：Sol 6.2 (`gpt-6.2-sol`)。推論設定の値は実行環境から確認できず未取得。Sol 5.6は実行していないため、ここで比較するのは同じモデルによるコード変更前後のみ。
- 開始SHA：`e03efef580a141564554329e027d94dd4a8353fd`（Draft PR #17）。変更前もこのSHAから本番用に新規ビルドした。
- Windows NT 10.0.26200、Node.js 24.18.1、npm 11.16.0、Next.js 15.5.22、Edge 154.0.4258.53（Playwright headless）。両ビルドで同じロックファイルと既存依存を使用。
- 同じローカルポートの `next start`、390×844と1440×1000。同一オリジンの通信のみ、毎回新規ブラウザコンテキスト、ブラウザキャッシュ無効、人工的な帯域制限なし。`load` 後1,200 msまでを集計したため、画面内リンクの先読みを含む。
- 速度は各ページ・各幅5回の中央値［最小〜最大］。一次試験ロードマップは補足として各幅1回の転送量・表示確認のみ。異なるビルドを順に測ったローカル観測であり、公開サイトの実利用速度や変更との因果は未測定。

## 不要な読み込みと修正範囲

基準ビルドではガイドのページチャンク `31c9f78c14b5b5a0`（非圧縮199,888 bytes、ブラウザでの圧縮本体50,383 bytes）が、3部品固有の表示文字列を持ち、部品を使わない工程能力にも配信されていた。共通レジストリで管理図デモ、答案骨子ビルダー、一次試験ロードマップだけをSSR付き `next/dynamic` へ切り替えた。変更後の共通ガイドチャンク `6d3399039cb3a67b` は132,328 bytesで、3部品の文字列はいずれも含まない。

実際の専用チャンクは、管理図 `7791.3b73fbaa3e92699e.js`（圧縮2,477 bytes）、骨子ビルダー `4617.e00c75a2c425ea9b.js`（13,602 bytes）、ロードマップ `8095.ac3ae5154b009d86.js`（3,836 bytes）。両幅でそれぞれのページだけが自分のチャンクを取得した。トップと工程能力はどれも取得しない。トップのページ固有チャンクは同一で、JS本体の+48 bytesは共有webpackランタイムの差。Next.js表示のFirst Load JSはトップ101→101 kB、共通ガイドルート145→127 kB。共通ガイドルート値には個別部品の追加読み込みを反映しないため、下の実測と分ける。

## 保全と検証

- 両幅で対象ページの本文テキスト、見出し、リンク先、canonical、本文の文字サイズ・行間が一致。ページ全体の横あふれとブラウザエラーなし。管理図の390px図スクリーンショットもSHA-256一致。
- 管理図は初期HTMLにSVGを維持。キーボードで平均移動4点、ばらつき増大6点を確認し、リセットで0点。骨子ビルダーの入力と原稿用紙・通常テキスト切替、ロードマップのnoteリンクの初期HTMLと案内を確認した。
- `check:ci` と管理図数値テスト4件が成功。Contentlayer 239件、公開238件、静的266ページ、prerender 249ルート、過去問130問を維持。sitemapの264 URLは同一、draft 404・既存管理図ツール200。既存のPage Data、Browserslist、Contentlayer Windows、複数lockfileの警告は変更しない。
- 本文、学習テンプレート、公開URL、依存関係、Pages Routerに変更なし。本番は未変更。
