# Content Model

## 1. Theme

主要テーマは次の4値を基本とする。

- `quality`: 品質をつくる
- `production`: 生産を整える
- `data`: データで確かめる
- `improvement`: 改善を仕組みにする

資格・理論は独立した中心テーマではなく、関連するThemeに接続した「学びを深める」分類として扱う。

## 2. ContentType

- `explanation`: 読み解く
- `visual`: 図で見る
- `simulation`: 試してみる
- `tool`: 現場で使う
- `case-study`: ケースから学ぶ
- `learning`: 学びを深める

1ページに主ContentTypeを1つ設定し、補助形式を必要に応じてタグで表す。

## 3. Difficulty

- `introductory`: 初めて学ぶ人向け
- `practical`: 基礎知識を現場で使う人向け
- `advanced`: 複数分野を統合して判断する人向け

難易度は文章の難しさではなく、必要な前提知識と判断の複雑さで決める。

## 4. タグ体系

タグは検索と関連付けに必要な最小数とする。

- 分野: 品質保証、生産管理、統計、SCMなど。
- 手法: FMEA、OEE、回帰分析など。
- 課題: 不良低減、人手不足、在庫過多など。
- 成果物: 規格、管理計画、評価表、研修資料など。
- 資格: QC検定、統計検定、技術士など。

同義語や表記揺れを増やさず、既存タグを優先する。

## 5. 一般記事メタデータ

現行ContentlayerのGuideは次を正本とする。

- `title`: 公開タイトル。必須。
- `exam`: `qc`、`stat`、`engineer`。パスからも正規化される。
- `slug`: 公開URLの識別子。
- `section`: サイト内の補助分類。
- `description`: 検索結果と一覧で使う要約。
- `tags`: 関連付けに使うタグ。
- `version`: コンテンツ版。
- `status`: `published` または `draft` 等の公開状態。
- `updatedAt` / `date` / `publishedAt`: 更新・公開日の情報。
- `themes`: 4テーマとの関連。任意。
- `contentType`: 主なコンテンツ形式。任意。
- `difficulty`: 必要な前提知識と判断の複雑さ。任意。
- `featured`: 主要導線で優先表示するか。任意。
- `draft`: 下書きとして扱うか。任意。

追加フィールドはすべて任意とし、既存frontmatterに値がなくても表示とビルドが壊れないようにする。一括書換えは行わず、更新する記事から段階的に付与する。

## 6. ケースメタデータ

ケースは一般記事と共通項目を持ち、次を追加候補とする。

- `context`: 匿名化した背景。
- `constraints`: 制約条件。
- `evidence`: 判断に使った情報の種類。
- `decision`: 判断内容。
- `deliverables`: 作成した成果物。
- `outcomeStatus`: 実施済み、提案、検証中など。
- `generalizableInsights`: 他の現場へ応用できる知見。
- `confidentialityNote`: 匿名化・非公開情報の扱い。

初期ケースは `src/data/cases.ts` の構造化データで管理する。将来MDXへ移行する場合も公開URLを維持し、同一内容を重複公開しない。

## 7. 一般記事とケースの違い

| 観点 | 一般記事 | ケース |
|---|---|---|
| 中心 | 概念、手法、適用条件 | 特定状況での判断過程 |
| 根拠 | 一次情報、理論、一般知識 | 匿名化した事実、制約、評価 |
| 成果物 | 例示可能 | 実際または再構成した成果物を明示 |
| 表現 | 一般化を優先 | 実績と提案を明確に区別 |

## 8. 重複コンテンツ防止

- 新規作成前に、既存URL、タイトル、主要タグ、検索意図を確認する。
- 同じ目的のページを資格別・用語別に複製しない。
- 同一テーマの資格向け説明は、一般記事へ接続するか、差分が明確な場合だけ分離する。
- 統合時は正本URLを決め、旧URLへ301リダイレクトを設定する。
- 同一本文を複数URLで公開しない。
