# Information Architecture

## 1. 基本構造

N-IE Labの中心は次の4領域とする。

1. 品質をつくる
2. 生産を整える
3. データで確かめる
4. 改善を仕組みにする

資格関連は「学びを深める」の副導線に置く。

- 技術士
- QC検定
- 統計検定
- 生産オペレーション
- TES
- 学習マップ

## 2. 主要領域

### 4テーマ

| 領域 | 主な役割 |
|---|---|
| 品質をつくる | 品質保証、QMS、品質設計、工程能力、検査、是正・予防を扱う |
| 生産を整える | 生産計画、工程管理、在庫、設備、IE、SCM、物流を扱う |
| データで確かめる | 記述統計、推定、検定、回帰、実験計画、可視化を扱う |
| 改善を仕組みにする | 標準化、監査、教育、KPI、組織運用、継続的改善を扱う |

### ケース

匿名化した実務課題を、背景、制約、情報収集、判断、成果物、一般化できる知見の順で示す。初期ケースは次の2件とする。

- `/cases/quality-standard-before-production`
- `/cases/third-party-testing-validity`

ケース一覧と指定2件の詳細ページを設け、機密情報を含まない再構成事例として公開する。

### ツール

計算、可視化、シミュレーション、判断補助を提供する。解説ページの代替ではなく、理解と実務適用を助ける。

### About・サービス導線

運営者の専門性、判断方法、提供可能な成果物、相談可能領域を示す。営業表現より、根拠と具体性を優先する。

## 3. 現行ルートの役割

現行実装はNext.js Pages Routerを使用している。既存ルートは明示的な移行指示がない限り維持する。

| ルート | 役割 |
|---|---|
| `/` | サイトの価値と主要テーマへの入口 |
| `/guides` | 学習領域を選ぶ入口 |
| `/guides/{exam}` | QC、統計、技術士のカテゴリ入口 |
| `/guides/{exam}/{slug}` | 個別の解説、参照、演習コンテンツ |
| `/guides/production` | 生産管理領域への入口 |
| `/tools` | インタラクティブツールの一覧 |
| `/tools/{tool}` | 個別ツール |
| `/learn` | 学習導線 |
| `/references` | 出典・参考情報への入口 |
| `/themes` | 4テーマを選ぶ入口 |
| `/themes/{theme}` | テーマ別に既存ガイド、ケース、ツールをつなぐハブ |
| `/cases` | 匿名化したケーススタディの一覧 |
| `/cases/{slug}` | 制約、判断、成果物、一般化できる知見を示すケース詳細 |
| `/about` | N-IE Labの目的、対象領域、知識の残し方 |
| `/services` | 相談可能な領域と成果物の例 |
| `/contact` | 問い合わせ先と相談時に必要な情報 |

## 4. ページ種別と責務

| ページ種別 | 主な責務 | 含めないもの |
|---|---|---|
| 入口 | 次に進む選択肢と全体像 | 長い詳細解説、大量の演習UI |
| 読み解く | 仕組み、因果関係、誤解、適用条件 | サイト全体の説明 |
| 図で見る | 構造、関係、判断フロー | 色だけに依存した意味付け |
| 試してみる | 操作、演習、シミュレーション | 過剰な理論説明 |
| 現場で使う | テンプレート、チェックリスト、手順 | 根拠のない万能手順 |
| ケースから学ぶ | 判断過程と成果物 | 実績の誇張、機密情報 |
| 学びを深める | 資格、理論、数式、答案演習 | サイト全体を資格中心に見せる構成 |

## 5. グローバルナビゲーション原則

- 4テーマを中心にする。
- 「学びを深める」は副導線として明確に分離する。
- ケース、ツール、About・サービスへ到達できるようにする。
- 同じURLへの重複リンクは、利用目的が異なる場合だけ残す。
- 入口では選択肢を絞り、詳細は下層へ委ねる。

## 6. ページ追加前の確認

- 主目的とページ種別が1つに定まっているか。
- 既存ページと役割や検索意図が重複しないか。
- 入口と出口のリンクが自然か。
- 既存URLを再利用できないか。
- 読者が次の行動を判断できるか。
