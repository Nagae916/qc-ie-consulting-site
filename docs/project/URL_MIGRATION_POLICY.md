# URL Migration Policy

## 1. 既存URL維持

- 公開済みURLは原則として変更しない。
- 情報設計、名称、デザインの整理だけを理由にURLを変更しない。
- 既存記事を削除せず、内容の正本と役割を確認する。

## 2. URL変更を認める条件

次のいずれかに該当し、現在のユーザー指示で変更が明示されている場合に検討する。

- 誤ったURLや分類が読者理解を継続的に損なう。
- 重複ページを統合する。
- 法的、セキュリティ、機密性の理由がある。
- 技術移行により維持不能で、互換ルートを用意できる。

## 3. 301リダイレクト

- 恒久移行では旧URLから新URLへ301を設定する。
- リダイレクト先は同等または上位互換の内容にする。
- リダイレクトチェーンとループを作らない。
- クエリパラメータを使う既存導線も確認する。

## 4. canonical

- 同一または実質同一内容の正本URLを1つ決める。
- canonicalは実際に閲覧できる正本URLを指す。
- 旧URLを残す必要がある場合も、重複公開を避ける設定を行う。

## 5. 重複記事の統合

1. URL、検索意図、被リンク、流入、更新状況を確認する。
2. 正本ページを決める。
3. 有用な固有内容を正本へ統合する。
4. 旧URLから301を設定する。
5. 内部リンク、サイトマップ、canonicalを更新する。
6. ビルド、リンク、主要画面、検索向け設定を確認する。

## 6. URL変更時の確認項目

- 旧URLと新URLのHTTPステータス。
- 内部リンクと外部流入への影響。
- canonical、OG、サイトマップ、構造化データ。
- 動的ルート、ISR、クエリパラメータ。
- モバイル表示と主要操作。
- 404、リダイレクトループ、重複本文の有無。
