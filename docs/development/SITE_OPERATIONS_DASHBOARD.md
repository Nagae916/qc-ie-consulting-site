# 運営ダッシュボード（ローカル試作）

## 閲覧と更新

Node.js 24で依存関係をインストールしたリポジトリから実行する。

```powershell
npm.cmd run dashboard:site
```

`.site-ops/dashboard.html` をブラウザで開く。HTMLは単独で表示でき、外部通信・APIキー・閲覧権限を必要としない。Linux/macOSでは `npm run dashboard:site`。ファイルはローカル生成物としてGit管理から除外し、公開サイトのURLや本番ビルドに入れない。

## 指標の定義

| 指標 | 現在の出典 | 更新方法 |
| --- | --- | --- |
| 公開ガイド、下書き、分類内訳 | `content/guides/{engineer,stat,qc}/` のfrontmatter | 再生成 |
| 明示テーマ、更新日 | 公開ガイドの任意フィールド `themes`、`updatedAt` | 再生成。未入力は0件として数えるが品質不良を意味しない |
| 中心テーマ、ケース、個別ツール | `src/data/n-ie-lab.ts`、`src/data/cases.ts`、`pages/tools/` | 再生成 |
| 開発ブランチ | ローカルのGit HEADと追跡先 | 再生成。remote先端やCIの成功は確認していない |
| 検索クリック、流入、相談、売上、稼働状況 | 未接続 | 出典と集計期間を決めた後に接続する |

この画面は生成時点のソースの数であり、公開サイトの実アクセス、検索順位、顧客行動、収益、CI結果を推測しない。検索流入はSearch Console、閲覧と導線はGA4等、相談・売上は別の記録元から接続する。接続する際はサイト側の認証やAPIキーをブラウザへ載せず、定義とデータ保護を確認する。

添付された参考画像に合わせて「4列×2段の指標カード→進捗内訳→状態ラベル付きのタスク表→未回答の問い」とした。幅が狭い場合はカードを2列、補助パネルを1列にする。タスク・未回答事項は現状調査に基づく試案であり、運営上の確定した優先順位ではない。
